# TOOF

Браузерная логическая игра на поле 10×10: соберите фигуру, зафиксируйте её и захватите 3 сектора из 4.

## Быстрый запуск

Игра остаётся статическим сайтом без сборщика.

- **Локально:** откройте `index.html` в браузере. Игра против бота и режим «на одном экране» работают сразу, без сервера и без интернета.
- **Онлайн:** нужен любой локальный HTTP-сервер, потому что Firebase не работает с `file://`. Например:

  ```bash
  python -m http.server 8080
  ```

  Затем откройте `http://localhost:8080`.

## Режимы

- **Ход** — закрашивается ровно одна клетка. Пока выделена фигура, на экране только кнопка «Подтвердить фигуру»; кнопка «Подтвердить ход» появляется после закрашивания клетки и снятия выделения. Если клетка уже закрашена, подтверждение фигуры сразу завершает ход. До закрашивания можно закрыть фигуру — ход останется у игрока; победная фигура завершает партию сразу.
- **На одном экране** — два игрока за одним устройством.
- **Язык и цвет** — в нижней части главного меню кнопка `RU / EN` переключает язык, а кнопка `🟠 / 🟣` выбирает цвет игрока; оба выбора сохраняются в браузере. Против бота выбранный цвет закрепляет сторону игрока (оранжевый — X, фиолетовый — O), а первый ход определяется монеткой независимо от цвета. На одном экране выбранный цвет получает Игрок 1, который ходит первым. По сети цвета сторон фиксированы: X оранжевый, O фиолетовый; настройка цвета второго игрока не влияет на отображение ходов соперника.
- **Против бота** — 7 режимов: Элементарный, Простой, Умеренный, Средний, Напряжённый, Сложный и Невыносимый. Бот берёт лучший из рассмотренных ходов, а на уровнях 2–7 в своих первых трёх ходах — случайно одного из трёх почти равных; тактический каскад (победа → достройка → блок → свои фигуры → поиск) работает на всех режимах. Элементарный смотрит только на ответ противника (1 ход вперёд), берёт одного кандидата и иногда не замечает даже решающий ход; Простой и Умеренный — тоже 1 ход, Средний — 2, остальные — 3. Сложность растёт за счёт числа кандидатов, ветвления и внимания: младшие режимы иногда не замечают заготовку или хороший ход, как человек, который не нашёл лучший вариант. Готовую фигуру на третий сектор видят все режимы, кроме Элементарного. Дебютное усиление прописано у каждого уровня: у Элементарного его нет, у Простого и Умеренного — 2 хода профилем Среднего, у Среднего — 2 хода профилем Напряжённого, у старших — 3 хода; в дебюте внимание полное. **Невыносимый** защищается от «скобы»: прямого и диагонального основания из пяти клеток, которое можно завершить до фигуры тремя способами; если основание на три сектора и почти построено, бот занимает клетку внутри него. На всех режимах первый ход в каждой партии выбирается случайно. На уровнях 1–4 по ходу партии изредка проскакивает профиль старшего уровня: шанс 5/10/15/15% на ход, профиль 5/5/5/6-го уровня соответственно. Три победы подряд повышают режим, три поражения — понижают. Ранги даются только за органический переход серией побед: 3 → 4 — Новичок, 4 → 5 — Любитель, 5 → 6 — Опытный, 6 → 7 — Профи; просто выбранный вручную уровень ранг не даёт. Каждая победа в 7-м режиме даёт ранг Мастер и увеличивает римскую цифру: Ⅰ, Ⅱ, Ⅲ и так далее. Средний и все уровни выше закрыты, пока игрок сам не дойдёт до них серией побед: Средний открывается после трёх побед на Умеренном. Серия побед сохраняется между выходами из игры. При смене ранга по центру экрана появляется короткая анимированная плашка; текущий ранг виден и на главном экране под названием игры. Доступ к режимам определяется только органически достигнутым рангом: старое сохранение с выбранным 4-м уровнем доступ не даёт. Смена сложности после игры или в её середине сразу запускает новую партию; до первого хода уровень меняется на месте.
- **Выход из партии** — выход в меню до конца партии считается поражением: серия побед сбрасывается, серия поражений пополняется. В онлайне такой выход приравнивается к сдаче и результат виден сопернику.
- **По сети** — случайный соперник, комната по ссылке/коду, друзья и приглашения. Ходы синхронизируются через Firestore, поэтому играть можно с телефона и компьютера, в том числе не одновременно.

- **Ничья** — если все клетки заполнены, а никто не захватил три сектора, партия заканчивается ничьёй (`Game.checkDraw()`). В онлайн-партиях ничья фиксируется тем же снимком (`over: true`, `winner: null`), попадает в статистику и не сбрасывает цепочку повышения ранга.
- **Сдача по сети** — когда соперник сдаётся, кнопка «Сдаться» у вас скрывается и показывается уведомление о победе. В случайной игре предлагается «Новая игра» с новым соперником; в игре с другом обоим предлагается реванш или выход. Если один выходит, партия закрывается для обоих и второй получает уведомление. Результат сдачи попадает в статистику обоих игроков. Для новых статусов партии нужно задеплоить правила: `deploy.bat` или `tasks.bat deploy-rules`.

## Онлайн: как устроено

- **Анонимный профиль** создаётся автоматически. Имя, код профиля, друзья и статистика хранятся в `localStorage` этого браузера. Регистрация не требуется.
- **Аккаунт Google** — необязательный. После входа профиль, друзья и статистика синхронизируются через Firestore и доступны на других устройствах. Ранги бот-режима (`users/{uid}.botRank`) тоже сохраняются в аккаунте: доступ к уровням 4–7 и подпись ранга восстанавливаются на любом устройстве.
- **Партия** хранится как документ `games/{id}` и журнал `games/{id}/moves/{ply}`. Клиенты присылают ходы `{ place, fix }`, где `fix` — список зафиксированных за ход фигур (старый формат с одной фигурой тоже читается); проверяют их общим редьюсером и проигрывают журнал заново.
- **Приглашения** — обычные документы Firestore со статусом `invited`. Друг увидит приглашение при следующем открытии игры, даже если вас не было в сети. Push-уведомления не используются.
- **Presence** — heartbeat в `users/{uid}.online` и `lastSeen`. Зелёная точка у друга означает, что он был в сети менее 90 секунд назад.
- **Согласие на игру** проверяется правилами Firestore: `active`-партию можно создать только на основе существующих записей в очереди, комнаты, приглашения или предыдущей партии (реванш). Код профиля резервируется в отдельной коллекции, поэтому два игрока не получат одинаковый код.
- **Онлайн-ранг** — число от 0 (без ранга) и выше; чем больше, тем сильнее игрок. Ранг хранится в профиле (`users/{uid}`) и в записи очереди. Случайный подбор сначала ищет соперника с тем же рангом, затем с ближайшим; при равной разнице выбирает дольше ожидавшего. Ранги обоих игроков фиксируются в документе партии на её начало.
- **Повышение ранга** — три победы над разными игроками, чей ранг выше вашего. Победы над слабыми или равными и ничьи цепочку не сбивают, но и не добавляют в неё; поражение сбрасывает цепочку; повторная победа над тем же соперником не считается. Ранг повышается до самого нижнего из рангов тройки: например, две победы над 1-м рангом и одна над 2-м дают 1-й ранг, а победа над 2-м остаётся в цепочке — для 2-го ранга нужно ещё две победы. После повышения в памяти остаются только соперники, которые всё ещё выше нового ранга.

### Ограничения бесплатного тарифа

Проект рассчитан на Firebase Spark (бесплатно). Ориентир: примерно 200–250 партий в день с учётом чтения журнала ходов. Для небольшого круга друзей этого достаточно. Платные сервисы и собственный сервер не нужны.

Если очистить данные браузера, анонимный профиль и локальные друзья пропадут. Для сохранности войдите через Google.

## Настройка Firebase (один раз)

Понадобится аккаунт Google и [Firebase Console](https://console.firebase.google.com/). Всё ниже — бесплатный тариф Spark.

1. **Создайте проект.**
   - Firebase Console → «Добавить проект».
   - Название любое, Google Analytics можно отключить.

2. **Добавьте веб-приложение.**
   - На странице проекта нажмите значок `</>` («Веб»).
   - Задайте имя, например `toof-web`.
   - Скопируйте объект `firebaseConfig`.

3. **Вставьте конфиг в игру.**
   - Откройте `js/firebase-config.js`.
   - Замените значения `PASTE_*` на свои:

   ```js
   const FIREBASE_CONFIG = {
       apiKey: '...',
       authDomain: '...firebaseapp.com',
       projectId: '...',
       storageBucket: '....appspot.com',
       messagingSenderId: '...',
       appId: '...'
   };
   ```

   Эти данные публичные. Безопасность обеспечивают правила Firestore.

4. **Включите вход.**
   - Authentication → «Начать».
   - Вкладка «Sign-in method» → включите **Анонимный** (Anonymous).
   - Там же включите **Google**. Укажите e-mail поддержки и сохраните.
   - Authentication → Settings → Authorized domains: `localhost` уже есть. Если будете открывать игру с другого домена, добавьте его.

5. **Создайте Firestore.**
   - Firestore Database → «Создать базу данных».
   - Режим: **Production mode** (правила мы задеплоим ниже).
   - Регион выберите ближайший, например `europe-west1`.

6. **Задеплойте правила и индекс.**
   - Установите Firebase CLI (нужен Node.js):

     ```bash
     npm install -g firebase-tools
     ```

   - В папке проекта выполните:

     ```bash
     firebase login
     firebase use --add
     ```

     Выберите свой проект и задайте короткий алиас, например `default`.

   - Затем:

     ```bash
     firebase deploy --only firestore:rules,firestore:indexes
     ```

   - Файлы `firestore.rules`, `firestore.indexes.json` и `firebase.json` уже лежат в проекте.

7. **Проверьте.**
   - Запустите локальный сервер (`python -m http.server 8080`) и откройте `http://localhost:8080`.
   - Меню → «🌐 По сети». Если всё настроено, появится экран лобби.
   - Откройте игру во втором браузере или в приватном окне и проверьте случайный подбор или комнату по коду.

8. **Публикация (необязательно).**
   - Если хотите играть не только на localhost:

     ```bash
     firebase deploy --only hosting
     ```

   - Firebase Hosting на Spark бесплатен. `firebase.json` уже настроен на статическую папку проекта.
   - После деплоя добавьте выданный домен в Authentication → Authorized domains, если Firebase не сделал это автоматически.

### Обновление сайта одним щелчком

Файл `update game.bat` обновляет правила Firestore и сайт. Запустите его двойным щелчком и дождитесь надписи `[DONE]`. Выносить файл из папки игры не нужно. Если всё же вынесете, запускайте с путём:

```cmd
"update game.bat" "C:\Users\danii\Documents\My Games\3-of-4-main"
```

Если конфиг не заполнен, онлайн-кнопки показывают инструкцию, а локальные режимы продолжают работать.

**Почему версия могла не меняться сразу.** Деплой берёт файлы из папки игры, а не из Git — коммит не нужен. Но `index.html`, JS и CSS раньше отдавались с `Cache-Control: max-age=3600`, поэтому браузер целый час показывал старые файлы, даже после успешного деплоя. Смена заголовка на сервере не очищает уже сохранённую копию — такие браузеры нужно было обновить один раз вручную (`Ctrl+F5` или ссылка с `?v=...`). Теперь включён `Cache-Control: no-store, must-revalidate`, а все локальные JS/CSS подключены с `?v=1.0.2`: каждый релиз меняет адреса файлов, поэтому старые копии больше не используются. При следующем повышении версии обновите `VERSION` в `js/rules.js`, `?v=` в `index.html` и число в `version.txt`, затем запустите `update game.bat`. Долго открытая вкладка раз в минуту сверяет `version.txt` и показывает плашку «Доступна новая версия» — перезагрузка происходит только по кнопке, чтобы не прервать партию. Само распространение деплоя по CDN занимает несколько секунд.

### Автоматический запуск задач (tasks.bat)

`tasks.bat` — небольшое приложение для автоматического выполнения повторяющихся задач по обновлению проекта. Двойной щелчок открывает меню, где задачу можно выбрать цифрой. Задачи также можно запускать сразу из командной строки:

```cmd
tasks.bat list                         :: список задач
tasks.bat deploy-rules                 :: только правила и индексы Firestore
tasks.bat deploy-site                  :: только сайт (Hosting)
tasks.bat update                       :: правила + сайт (как update game.bat)
tasks.bat all                          :: все задачи с флагом AUTO
tasks.bat all -dry                     :: показать команды без выполнения
tasks.bat deploy-rules "C:\path\to\game" :: запуск из другой папки
```

| Задача | Команда | Назначение |
| --- | --- | --- |
| `deploy-rules` | `firebase deploy --only firestore:rules,firestore:indexes` | новые проверки правил Firestore вступают в силу только после деплоя |
| `deploy-site` | `firebase deploy --only hosting` | обновление статического сайта |
| `update` | обе команды подряд | полное обновление проекта |

`deploy.bat` — ярлык для задачи `deploy-rules`: двойной щелчок деплоит только правила и индексы, сайт не трогает.

Флаг `-dry` печатает команды, но не выполняет их — удобно проверить, что будет запущено. При ошибке любая задача печатает `[FAIL]`, а сценарий завершается ненулевым кодом.

Чтобы добавить задачу, допишите в реестр в начале `tasks.bat` строки `set "TASK_n_ID/NAME/LABEL/AUTO"` и создайте метку `:taskИмя` с телом задачи. `TASK_n_AUTO=1` включает задачу в режим `all`; новая задача автоматически появляется в меню (всего до 9 задач — пункты меню выбираются цифрами).

### Автоудаление старых данных (бесплатно)

Игра сама пишет поле `expiresAt` в партиях, комнатах и заявках в друзья. Чтобы Firestore удалял их автоматически, один раз включите нативную TTL-политику (бесплатно, без сторонних сервисов) в консоли Firestore → TTL или через gcloud:

```bash
gcloud firestore fields ttls update expiresAt --collection-group=games --enable-ttl
gcloud firestore fields ttls update expiresAt --collection-group=rooms --enable-ttl
gcloud firestore fields ttls update expiresAt --collection-group=friendRequests --enable-ttl
```

Без TTL данные просто перестанут быть видны интерфейсу (игра по истечении скрывается из списка), но будут занимать место в базе.

## Тесты

Логика ядра и сетевого протокола проверяется без браузера:

```bash
node --test
```

Или через npm:

```bash
npm test
```

Тесты лежат в `tests/` и загружают браузерные скрипты через Node `vm`, поэтому сборщик не нужен.
